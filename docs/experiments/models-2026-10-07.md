# GPT-6 Luna migration evaluation

The deployed predecessor was GPT-5.6 Luna low, not Terra. These local evaluations
used the existing authorized server key, isolated DynamoDB Local quota counters,
the actual production classifier, 25-item maximum batches (25+15), full output,
2,048 output tokens including reasoning, and the unchanged 15-second deadline.
Each effort classified the same 40 authored difficult cases three times, shuffled
identically. These are repeated cases, not 120 independent products. No provider
results were reused during this comparison.

| Setting           | Calls completed | Identity/status | Preparation checks | Complete outcomes | Mean request | Range       |
| ----------------- | --------------- | --------------- | ------------------ | ----------------- | ------------ | ----------- |
| GPT-6 Luna low    | 6/6             | 117/120         | 52/57              | 112/120           | 5.80 s       | 4.01–8.69 s |
| GPT-6 Luna medium | 6/6             | 119/120         | 57/57              | 119/120           | 7.05 s       | 6.02–8.64 s |

Neither setting produced a false recognized identity against these expected labels.
Low omitted preparation for broth, whole milk, soy sauce and shredded cheese in
one repeat; it left cauliflower rice as a taxonomy gap in all three. Medium fixed
all preparation misses and recognized cauliflower in two of three repeats. Its
remaining miss was a conservative taxonomy gap. Microwaveable brown rice and canned
unsalted black beans were correct throughout. Composite foods, ambiguous names,
plant-based substitutes, nonfood and an instruction-injection name were included.

Choose medium for standardization and retain low for user-initiated requests.
`standardization_reasoning_effort` is a server-only Terraform override; it reaches
the API and worker, and the classification cache keys use its effective value.
It does not alter interactive effort, quantities, batch size, timeouts or production
quotas. Existing saved classifications are not discarded merely because the model
changes. An unclassified food still needs review; identity never establishes
allergen safety or measured package quantities.

Three actual local recipe API requests using Luna low completed successfully in
6.806, 3.647 and 5.335 seconds. They produced egg/spinach/cheddar, cooked-rice/canned-bean,
and pasta/tomato ideas with explicit recipe measures. The egg ideas were only modestly
different (omelet and scramble), so this is an API/quality smoke test rather than a
comprehensive recipe evaluation. No recipe was saved or inventory deducted.
Repeating those three requests reused persisted results in 27, 20 and 21 milliseconds
with zero additional provider calls.

This small targeted sample supports the chosen defaults, not a production accuracy
or latency guarantee. Earlier 5.6 results also used different batch sizes; do not
attribute their timing differences solely to the model upgrade. No Sol comparison
was needed to establish the Luna migration; Sol remains an explicit local option.

Reproduce with `node scripts/full/evaluate.mjs gpt-6-luna low|medium` (choose one
effort, not the literal pipe). Detailed synthetic-case reports remain in ignored
`artifacts/local/model-migration-*.jsonl`. The shared real-local 50-call daily budget
applies; no counter reset is part of this procedure.
